# 模型设置聚合改造

## 范围与基线

基于完整 fork 分支 `codex/comfyui-native-media` 的 `b106c7b` 实施。原型位于另一个 worktree 的 `web/prototypes/model-settings/`；本改造进入实际应用源文件，复用现有配置持久化、模型目录、协议及 ComfyUI 执行合同。

模型设置使用单一服务列表和添加入口。用途导航包括文本、图片、视频、音乐、配音、音效和其他音频；默认模型控件回到用途面板。旧 `section=models` 入口进入聚合页面。

## 实现结构

- `channel-settings-pane.tsx`：统一列表、搜索、用途导航、展开模型、服务启停与管理；继续复用官方账户连接、模型目录更新和删除持久化。服务保持配置顺序，ComfyUI 不特殊置顶。
- `model-service-dialog.tsx`：持有唯一 AppDrawer、类型选择器、按类型隔离的草稿和忙碌状态。ComfyUI 在原位加宽，来回切换不重新打开容器。新建流程切换类型会清空凭据输入；已有服务不允许改变接入类型。
- `model-service-editor.tsx`：API 连接、模型目录、手动模型及现有协议编辑内容，共用统一侧栏。
- `native-comfy-settings-modal.tsx`：保留历史文件名，但现在只渲染 ComfyUI 表单内容，不创建第二个弹窗。连接、工作流、模型与参数、映射、最终输出共处一张表单；多工作流保留独立草稿，一次保存。
- `native-comfy-mappings.tsx`：直接展开动态来源、启停、素材槽位和必需性；完整字段约束编辑沿用共享组件，核心来源调整不需要逐个展开字段。
- `model-settings-catalog.ts`：从实际 API graph 和目标节点定义提取数值、字符串、布尔值、模型选项及参数限制。业务常用字段优先显示，节点连线不变成表单输入。固定值修改同时更新图与对应字段值，保留动态绑定和随机策略。

保持现有 ModelChannel、modelProfiles、audioUses、graph、fields、outputNodeId 和 outputField 数据结构。用户原有画布缓存修复涉及的两个文件未改，后端及 ComfyUI 服务未改。

## 验证记录

1. 正式前端 `bun run build` 通过，包含 TypeScript 检查；本次修改的 TS/TSX 文件 ESLint 通过。
2. 六个相关测试文件共 53 项通过：模型设置、原生协议、服务预设、渠道状态、配置持久化及助手默认模型。新增覆盖音乐和语音字段、布尔值、节点枚举、数值范围以及无关图连线保留。
3. 浏览器读取现有两台局域网 ComfyUI 的版本和模型节点清单成功，分别返回 0.33.0 和 0.37.0。H3 和 Music3 表单来自各自真实工作流，呈现不同字段。
4. 用独立临时服务导入实际图片工作流，将种子设为 303；往返切换 API / ComfyUI 后确认侧栏与类型选择器 DOM 实例不变、草稿保留。保存后刷新并重开，名称、种子及输出字段恢复正确。
5. JSON 语法错误就地显示；未应用 JSON 时禁止切换类型及保存。共享工作流草稿切换正常。检查明暗主题、390px 窄窗口、表单滚动和固定保存按钮，没有横向溢出或浏览器控制台错误。
6. 移除临时服务后，对浏览器重新加载的完整配置计算摘要，与验收前一致。原有服务、工作流、默认选择及连接配置未因验收改变。
7. 初始设置列表页 Lighthouse 无障碍得分 100，自动检查无失败项。该结果不覆盖所有打开后的侧栏状态，也不是整站性能结论；侧栏另做上述交互与视觉检查。

本机日志、截图、Lighthouse JSON 和私有配置备份均在忽略目录 `.local/design-evidence/model-settings-implementation/`，不得加入 Git。

## 实际边界

- 本轮验证设置、节点清单读取和真实配置保存，未重新执行媒体生成，也未将语音字段的表单支持记作配音模型生成验收。
- 原生连接检查仍面向无需鉴权的现有服务；未新增带鉴权的 ComfyUI 接入合同。
- 音乐、配音和音效仍共用现有默认音频模型字段，界面明确显示；没有创建后端不消费的独立默认项。
- 图中的标量字段和节点选项可编辑，但任意第三方节点组合的执行兼容性仍以实际任务预检和生成结果为准。更改用途不会自动更换模型、重写节点图或安装模型。
- 改造通过完整 fork 分支交付；桌面安装包发布和上游 PR 更新分别推进。
