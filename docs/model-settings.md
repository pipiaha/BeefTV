# 模型设置

模型设置分为“服务接入”和“默认模型”。先配置服务，再在默认模型页选择创作时使用的模型；同一个服务可以提供多种生成用途。

## 选择接入方式与用途

页面直接显示两种添加入口：

- **API 模型服务**：填写服务商地址和鉴权信息，再读取目录或手动添加模型，按模型维护能力与请求协议。
- **ComfyUI 工作流**：连接本机或局域网的原生服务，导入 API 格式的工作流。

服务列表按接入方式分组，外层直接列出文本、图片、视频、音乐、配音、音效、其他音频。筛选数量表示支持该用途的服务数；一个服务可以出现在多个用途下。筛选不会删改其他用途的模型。

音频是输出媒体类型，配音是其中一种业务用途。音乐、配音、音效分别配置，不能因为都输出音频文件就视为同一种生成能力。每个音频模型或工作流通过 `audioUses` 保存实际用途，可多选；未分类的进入“其他音频”。仅有明确的内置 `/audio/speech` 协议时，默认识别为配音；不凭模型名称推断音乐或配音。

分类不会自动安装模型或改变生成协议。新添加的音乐、音效模型不会默认套用配音协议，需选择服务实际支持的协议。某个工作流是否支持人声、参考音频或声音克隆，仍取决于其模型、节点和输入映射。

## 配置 ComfyUI

左侧“服务连接”管理名称和地址；工作流共用该连接。当前连接表单面向无需鉴权的原生服务，地址只填写 HTTP(S) 主机与端口，不附加端点路径。

“检查连接”只读取版本和节点清单，不提交生成任务。工作流页“读取模型选项”使用同一检查接口，为可识别的模型文件字段提供目标服务上的选项。检查成功与生成测试成功是不同状态。

每个工作流依次设置：

1. 工作流名称与输出媒体类型。音频工作流另行设置音乐、配音、音效用途。
2. 上传或粘贴 ComfyUI 的 **API 格式 JSON**。浏览器界面格式的 JSON 会被拒绝，并给出导出说明。
3. 目标服务的模型文件与常用数值参数。绑定到任务参数或随机策略的字段在基本表单中只读，避免覆盖运行时绑定。
4. 最终输出节点。常见保存节点可自动识别；多输出或自定义节点需要手动选择。
5. 按需展开“高级设置”，调整输出字段、输入映射、JSON 或缓存释放策略。

编辑 JSON 后需“检查并应用”，再“保存全部更改”。尚未应用的 JSON 会阻止保存和切换工作流，避免无意丢失编辑内容。取消关闭弹窗会放弃本次草稿。

更换文件或粘贴新工作流会重新提取输入映射；要调整已有图并尽量保留匹配节点的映射策略，使用高级设置中的“编辑 API JSON”。节点连线不作为可覆盖输入。

常见视频节点的输出字段可能是 `images` 或 `gifs`，不能仅按“视频”分类改成 `videos`。以实际保存节点返回的文件字段为准。

## 保存与引用

已有工作流改名保留其标识，继续使用原有任务和默认模型引用。新增工作流自动避开已有标识。保存共用连接时保留其他工作流、鉴权信息和连接选项。

移除工作流或服务后，默认模型会按可用项更新。已有任务和素材保留。混合了其他协议模型的旧服务不会由 ComfyUI 编辑器直接覆盖，需要先整理为独立服务。

本页只管理 BeefTV 的连接与工作流配置；目标 ComfyUI 的节点安装、模型文件和启动参数由其部署维护。
